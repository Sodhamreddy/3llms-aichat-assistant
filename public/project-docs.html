Executive overview

Product purpose

A business-level view of what the product does and why it matters.

1

Ask once

The user types one question into Excelliq instead of asking the same question separately in different AI tools.

2

Run multiple models

The system sends that question to the selected models, such as ChatGPT, Gemini, and Claude.

3

Receive one final answer

Claude reads the model responses and creates one polished final response for the user.

Main value: the user gets a stronger answer by combining multiple AI perspectives, while still seeing the individual model responses when needed.

Most important section

Detailed user flow

This shows exactly what a user experiences from first visit to final AI answer.

First-time user journey

A new user must create an account, choose a mode, connect models, and finish setup before entering the main chat screen.

Browser Mode is the default because the product is designed to work without official API keys.

User opens the application

The user sees the landing page and clicks Get Started or Start for free.

User creates an account

The user signs up with email/password or Google. Supabase stores the user account and profile.

User chooses Browser Mode or API Mode

Browser Mode uses saved provider logins. API Mode uses official provider keys.

User connects LLM accounts

The user connects ChatGPT, Claude, and Gemini. Each provider is saved under the user's isolated browser profile.

User clicks Finish

The backend validates the sessions and marks each provider as connected, expired, or error.

User enters the chat screen

Onboarding is marked complete, so the user should not see setup again after future login.

Returning user flow

Existing users should go straight to chat if onboarding is already complete.

User logs in

The user logs in using email/password or Google.

App loads saved profile

The backend retrieves the user's profile, client ID, preferences, onboarding status, and LLM session status.

User asks a question

The user types a prompt in the chat interface.

App checks connected models

If one model is expired, the system can skip it or guide the user to reconnect it.

Backend sends the prompt

Playwright opens the saved browser profile and submits the prompt to selected providers.

Individual answers are collected

ChatGPT, Gemini, and Claude responses are shown in separate cards.

Claude creates final synthesis

Claude receives the original question plus the model responses, then writes one final answer.

User can ask follow-up questions

The system can continue the conversation using the previous answer as context.

Functional explanation

The user works in the web application. The application communicates with a backend server. The backend connects to Supabase for user information and controls browser sessions for ChatGPT, Claude, and Gemini.

Technical explanation

The frontend is a React/Vite application. The backend is an Express server. Playwright controls browser sessions. Supabase stores users, preferences, and session status.

Prompt execution

How an answer is generated

Functional flow

The user asks one question. The app sends it to multiple models. Each model answers. Claude then reads the responses and prepares the best final version.

Technical route

The frontend calls POST /run-prompt. The backend streams progress events while Playwright collects responses and sends final data back to the frontend.

Frontend
  -> POST /run-prompt
  -> Backend validates client_id and selected models
  -> Playwright opens saved browser profile
  -> Prompt is sent to ChatGPT, Claude, and Gemini
  -> Responses are read from each provider interface
  -> Claude receives the synthesis prompt
  -> Final answer is streamed back to the user
Final synthesis behavior: Claude is instructed to understand the user's goal, compare all responses, keep strong claims, remove weak claims, resolve conflicts, and produce one clean answer without source labels or extra commentary.

Stored safely: browser cookies, authenticated browser sessions, client profile path, and provider connection status.
Not stored: ChatGPT passwords, Claude passwords, Gemini passwords, or third-party account passwords.

Client isolation

Each user has a unique client_id. Each client gets a separate Playwright browser profile so accounts do not mix.

Production risks

What can go wrong after deployment

Third-party interface changes: ChatGPT, Claude, or Gemini can change their product interfaces, which may break selectors or response-reading behavior.
Captchas and bot checks: Providers may ask users to complete additional login verification.
Session expiry: Browser cookies can expire, so users may need to reconnect accounts.
Remote browser smoothness: The deployed preview is screenshot-based. For a smoother experience, use noVNC, WebRTC, or a managed remote browser service.
Server resources: Browser automation uses more CPU and memory than a normal API server.
Persistent storage: If browser profiles are not stored on persistent disk, users will lose login sessions after restart.
